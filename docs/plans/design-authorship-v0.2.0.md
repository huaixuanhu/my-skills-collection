# design-authorship v0.2.0 实施计划

衍生自：[2026-09-23 调研报告第 8 节](../research/design-authorship-product-design-2026-09-23.md)。本文件是该建议经用户确认并补充重点后的实施计划；调研报告继续保留来源与研究边界，不作为并行实施计划。

日期：2026-09-23。分支：`codex/design-authorship-product-design`。实施前提交：`26c072d`。

## 1. 已确认目标

在现有 `design-authorship` 内升级至 `v0.2.0`。保留 UI、幻灯片与图示能力，重点加强两件事：

1. 注意力的连续性：整页的入口、主次、相关信息和下一步应当连贯；操作与窗口变化后仍能理解当前上下文。设计预期与实际眼动证据分开。
2. 可维护的统一设计语言：把经过确认的结构、语义与视觉规则保存为项目依据，使验收、体验反馈、修改维护和再次验收形成有方向的循环，避免每轮局部修改改变整体语言。

设计依据覆盖信息优先级、比例、分组边界、排版节奏、形状含义、图文关系、状态及操作反馈，不能仅记录颜色与圆角。它允许有证据、在授权范围内的演进；偶然偏差和未经选择的试验不能自动成为新规范。

## 2. 实施范围

### stage1.1 产品结构与注意力连续性

补充按任务推导结构的参考文件；在入口、方向选择、整页构图和交互参考中明确：真实内容先行；有未决选择才比较方案；通过入口、关系、反馈和下一步设计注意力衔接；不规定唯一观看路径或强制移动键盘焦点。

### stage1.2 持续设计语言与反馈循环

增强现有设计上下文与评审参考。复用项目已有的设计文档和已接受产物，记录规则的角色、原因、允许变化及代表性证据。每次维护定位反馈来源、原因与影响范围，对照任务和原有设计依据验证；经过接受或既有委托覆盖的演进再同步文档、组件和相关证据。

### stage1.3 验证与同步

同步入口、目录、界面元数据、版本、测试场景、变更记录和版本证据。保留适用的小修复、卡片集合、幻灯片和图示路线。独立检查真实决策；在现有工具支持下用有限的合成界面维护案例检查实现和连续修改。记录所做检查的范围，不从有限案例宣称稳定美学收益。

运行仓库总验证及官方 skill 格式检查。测试不设置卡片数量、审美分数或固定风格门槛。

## 3. 本地执行边界

本次改动限该 skill、对应测试、索引、版本记录与本轮计划/调研状态。本地保存提交。其他 skill、下游项目、安装链接、远端 push 和 tag 不在本次改动中。

现有安装可能通过符号链接读取本仓库；因此改动源码可能在后续读取时可见，并不证明正在运行的任务已重新加载。没有通过安装目录编辑源码。

## 4. 完成记录

本地候选版已实现，证据见 [v0.2.0 版本记录](../../releases/design-authorship/v0.2.0.md)。

- stage1.1、stage1.2：已完成；仍使用同一个 skill，新增一个按需读取的产品结构参考文件。
- stage1.3：仓库总验证（3 个 skill、9 组回归）、官方格式检查、目录同步和引用可达性检查通过。26 个场景输入经过结构检查；另有 5 个独立情境的实际决策检查通过。
- 合成维护练习完成两轮源码修改，分别通过 18 和 27 项含重叠的模拟状态检查；已有设计依据保留，未把未经视觉验收的实现提升为新基线。
- 待补证据：浏览器 URL 安全策略拒绝了本地文件访问；后续浏览器检查停止。实际页面渲染、键盘/触摸体验和视觉对照尚未完成。因此本轮结论限于本地候选规则、独立决策和源码状态行为，不宣称稳定美学收益。

临时服务和浏览器标签已关闭；合成材料保存在临时目录，未提交生成日志或迁移真实项目。后续如开展实页验证，应先使用平台明确允许的验证方式；不能通过改换入口绕过已知策略拒绝。
