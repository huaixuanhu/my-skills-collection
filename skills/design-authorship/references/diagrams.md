# Diagram Mode

Use this reference for processes, systems, architectures, responsibilities, boundaries, relationships, and explanatory figures.

## Semantic Grammar

- Use arrows only for direction, transformation, or causality.
- Use undirected lines for association when direction is not part of the claim.
- Use numbering only for real order.
- Use boundaries only for real ownership, scope, trust, or system separation.
- Use the same shape for the same object type.
- Let size differences represent importance, quantity, or hierarchy only when the mapping is stated or obvious.
- Use color for category, state, ownership, or scope, with a non-color cue when the distinction matters.

Consider axes, brackets, regions, swimlanes, matrices, continuous bands, and detail callouts before defaulting to rounded nodes and arrows.

## Concept Images

Most technical diagrams do not need image generation. Use a concept-image pass only when an illustrative metaphor or spatial world is part of the communication goal. Keep generated illustration separate from the exact diagram grammar and technical evidence.

## Verification

Inspect the diagram:

- at its intended size and at approximately 25 percent scale;
- in grayscale;
- with color mentally or mechanically removed;
- along every arrow and boundary;
- against the source architecture, process, or evidence.

The main relationship should remain legible without relying on decoration or the accompanying rationale.
