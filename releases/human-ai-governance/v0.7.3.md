# human-ai-governance v0.7.3

Date: 2026-08-27

Status: validated canonical candidate

## Scope

- Add index-first plan routing when nested children, parallel branches, multi-session continuation, or retained historical plans make the current entry ambiguous.
- Keep a single clear plan direct and avoid fixed activation thresholds based on file count, token count, project tier, or project importance.
- Treat `PLAN_INDEX.yaml`, `PLAN_INDEX.md`, or an existing registry as a compact routing read model that cannot grant scope, authority, approval, or completion.
- Apply `default`, `conditional`, or `evidence_only` load policy before opening plan bodies.
- Limit default plan context to the matched current plan, necessary parent chain, status owner, and evidence required for the affected claim.
- Separate `lifecycle_status`, `authority_state`, and `load_policy` so completion does not silently remove a still-current contract.
- Define `complete + consumed + evidence_only` as completed work whose result has been absorbed by another owner source and whose plan remains available for claim-scoped evidence or history.
- Update the index and a mutable plan-header mirror together at closeout while preserving immutable or evidence-bound plan text.
- Keep large indexes cheap through compact root routing, workstream indexes, or deterministic matched-entry selectors rather than full-registry context loading.

## Compatibility Contract

The five-tier model, authority boundaries, reasoning routing, v0.7.1 writing modes, and v0.7.2 technical-language choices remain unchanged. Plan indexing affects context selection only. It cannot weaken implementation, validation, evidence, safety, authorization, completion criteria, or owner-source verification.

The index remains secondary to its owner sources. A stale index yields to current plans, receipts, contracts, authorization records, code, tests, and Git evidence. Evidence-bound plans retain stable paths and content even after their default load policy changes.

## Behavioral Evidence Ceiling

- Added scenarios for a simple direct plan, nested consumed history, a completed current baseline, immutable evidence-bound closeout, a stale index conflict, and a large index.
- Added semantic checks for proportional activation, state-axis independence, load-policy ordering, owner-source precedence, evidence retention, stable paths, and compact index scaling.
- No independent model-output matrix was run for this release. The deterministic checks prove that the skill package carries the routing contract; they do not prove identical retrieval behavior in every future repository or model response.
- Prior v0.7.1 writing evidence and v0.7.2 terminology invariants remain applicable because their routes and capability boundaries are unchanged.
