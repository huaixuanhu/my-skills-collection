# human-ai-governance v0.6.0

Date: 2026-08-10

Status: validated canonical release

## Scope

- Keep `xhigh` for relatively simple, bounded work in the main workspace.
- Treat Max and Ultra as peer primary modes whenever a task has meaningful complexity.
- Prefer Max when deep serial reasoning, causal continuity, high coupling, or difficult plan closure dominates.
- Prefer Ultra when several meaningful investigation, implementation, test, or review streams can proceed independently before reconciliation.
- Preserve Codex discretion over delegation, coordination, and writing instead of fixing Max or Ultra to one agent shape.
- Avoid over-defensive Ultra execution, including unnecessary guards, documents, tests, agents, or scope expansion.
- Allow a temporary, narrow Max single-writer recovery slice only after evidence of repeated coupled failures, persistent validation deadlock, or cyclic breakage.

## Deterministic Evidence

- Package regression: passed.
- Preflight behavior regression: passed; the mechanical preflight behavior remains unchanged.
- Aggregate repository validation: passed.
- Official Codex skill validator: passed.

## Model Behavior Evidence

Model: `gpt-5.6-sol`

Reasoning efforts: `xhigh`, `max`, `ultra`

- Completed 36 isolated paired runs: six scenarios, three reasoning efforts, and two skill versions.
- The v0.6.0 candidate matched the accepted routing in all 18 candidate runs.
- Results consistently selected `xhigh` for bounded simple work, Max for coupled serial diagnosis, Ultra for parallel work, staged Ultra-to-Max handoffs when the task structure justified them, and temporary Max single-writer recovery only for the demonstrated failure loop.
- The v0.5.1 baseline showed routing inconsistency in five of the six scenario families, including reversed Max/Ultra roles, complex-task downgrades, and inconsistent recovery behavior.
- Generated evaluation run logs were not retained in the repository.

## Release Boundary

This release changes the reusable skill, its generic scaffold metadata, tests, and release evidence only. It does not migrate downstream projects, change installed skill links, alter model configuration or permissions, or perform publication actions.
