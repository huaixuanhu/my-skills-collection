# human-ai-governance v0.7.2

Date: 2026-08-27

Status: validated canonical update

## Scope

- Add an explicit technical-language choice with two values: `default` and `plain`.
- Use `default` when the user does not choose. This keeps normal Codex terminology and does not add a mandatory clarification question.
- Activate `plain` only from an explicit user choice, scoped to the current task, deliverable, or content unit unless the user sets a broader scope.
- Route the existing v0.7.1 writing mode first, then apply the terminology choice inside that writing mode.
- Keep the two controls independent: terminology choice cannot activate, deactivate, replace, weaken, or reshape engineering-governance or audience-facing writing.
- Change wording only in `plain` mode. Preserve reasoning, planning, implementation, tools, validation, evidence, safety, authorization, and completion criteria.
- Preserve exact identifiers, code, commands, paths, configuration keys, error text, formulas, and necessary technical terms. When simplification would lose meaning, retain the term and explain it in common words.
- Keep terminology checks editorial and semantic. Do not add jargon quotas, word blacklists, reading-level thresholds, regex gates, or AI-detector gates.

## Compatibility Contract

The v0.7.1 writing system remains the content-structure control. Engineering-governance content stays operational and reproducible. Audience-facing content keeps its intended voice, narrative, organization, rhythm, genre, and presentation logic. The v0.7.2 terminology choice only changes how technical meaning is worded within the selected writing mode.

`plain` does not mean shorter, less exact, or less capable. A plain explanation may be longer when extra explanation is required to preserve meaning.

## Behavioral Evidence Ceiling

- Added five scenarios covering omitted terminology choice, plain engineering explanation, audience-facing default terminology, audience-facing plain terminology, and a high-consequence plain handoff.
- Added semantic checks for fallback behavior, explicit activation, writing-mode independence, engineering-capability invariants, and exact-token preservation.
- No independent model-output matrix was run for this small release. The deterministic checks prove that the skill package carries the contract; they do not guarantee identical wording in every future model response.
- The v0.7.1 model evidence remains the evidence base for the unchanged writing-mode behavior. This release adds a separate terminology control around that behavior.

It excludes downstream project migrations, changes to installed skill links, tag creation, release publication, plugin packaging, connector changes, and deployment.
