# human-ai-governance v0.7.5

Date: 2026-08-31

Status: validated for main

## Scope

- Default conversational engineering plans, progress, evidence, results, and handoffs to `compact`: conclusion or state first, then applicable evidence, material risks or uncertainty, required decisions, and next action.
- Remove repeated background, tool diaries, generic reassurance, and secondary implementation detail before any decision-relevant fact. No fixed headings, empty fields, word limits, jargon quotas, or shortening percentages are required.
- Introduce each problem with its affected subject, observed behavior, and current handling in natural sentences. Identify who acts or approves what when known; allow sufficient context instead of the shortest possible answer, and never invent an unknown cause or owner.
- Use `expanded` when requested or needed for explanation, safe execution, or reproducibility. Preserve complete formal plans, specifications, runbooks, evidence records, and other requested artifacts.
- Keep exact commands, paths, errors, identifiers, quantities, evidence limits, and authority boundaries when needed; distinguish inspected, changed, validated, committed, pushed, deployed, and activated.
- Honor standing user or project plain-language instructions without asking the user to repeat them. Prefer a common exact substitute for unfamiliar terminology; retain and explain a necessary term in the user's language.
- Front-load engineering communication in the description and catalog. Ordinary bounded communication does not create tiers, plans, logs, gates, or new approval turns; unrelated chat, translation, and prose remain outside this skill.

## Compatibility and Activation

Review density controls conversation presentation only. It does not reduce reasoning, investigation, implementation, validation, evidence, safety, or completion requirements. The five-tier model, reasoning-mode routing, writing-mode routing, explicit terminology choices, plan lifecycle, and persistent-recovery authority remain in place. `compact` does not silently select `plain`, and neither choice changes a task's authority.

The generic preflight changes only its version marker. No review-density or terminology script gate was added. Existing project adapters require separately approved migration; this change does not rewrite global instructions or downstream projects.

The current user-level installation is a symlink to the canonical directory. Source edits are therefore visible on subsequent reads without changing the link. This is not proof that every active session has reloaded the skill or that every future task will invoke it. Description matching, explicit skill use, installation state, and actual platform invocation are separate claims.

Official guidance checked on 2026-08-31: Codex initially reads skill names and descriptions, may shorten that list, and selects skills by description match. It detects skill changes automatically; if an update does not appear, restart Codex. This supports front-loaded triggers and a conditional refresh instruction, not a guarantee that every engineering message invokes the skill. See [OpenAI Build skills](https://learn.chatgpt.com/docs/build-skills).

User review requested less compressed problem descriptions with an explicit affected subject and observed phenomenon before the handling state. The refinement keeps natural sentences, identifies the next actor and approval action when known, and allows more context without requiring repeated subjects or inventing unknown ownership.

The skill description, version, terminology selection, reasoning routes, execution authority, and preflight code are unchanged by this refinement. Earlier routing and broad compatibility evidence remains relevant within that ceiling; the initial matrix does not itself prove the new subject-clarity behavior. A narrow correction now keeps the provided review entrypoint alongside the plain-language subject. The refinement used two independent `xhigh` batches, three responses each: the first exposed the missing review pointer and the second checked the final correction.
