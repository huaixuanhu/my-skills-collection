## Model Behavior Evidence

Model: `gpt-5.6-sol`

Reasoning efforts: `max`, `ultra`

- Completed 34 isolated candidate runs in total: an initial five-scenario matrix and a deeper 12-scenario adversarial matrix, each run at both requested reasoning efforts.
- The 24-run deep matrix scored 239/240, with 24 strong passes, no critical under-validation, no authorization bypass, no invented per-action approval inside an approved execution envelope, and no unbounded retry or validation loop. See [`v0.7.0-deep-evaluation.md`](./v0.7.0-deep-evaluation.md).
- Large-data consumer change: both modes reused the unchanged immutable dataset receipt, selected focused downstream validation, and kept the handoff below full-dataset, production, publication, and remote-state claims.
- Large-data semantic invalidation: both modes reused the unchanged raw-source receipt while reopening schema v4 transformation, integrity, mixed-partition, and downstream-compatibility claims. They required current validation for all 12 rebuilt partitions plus affected dataset-wide invariants, and tied the five-hour aggregate validator to actual acceptance coverage or a repository gate rather than its duration.
- Boundary-owned Tier 5 defense: both modes retained adapter validation, runtime risk limits, and preflight as independent controls while rejecting same-owner helper duplication and a silent catch-all fallback.
- Full-access platform configuration: both modes continued already approved local work without inventing a platform approval, then stopped before unapproved push and production deployment.
- Complex component and simple glue decision: both modes recommended implementing the narrow parser locally and required evidence-based comparison before selecting a distributed scheduler or accepting long-term custom ownership.
- Deep adversarial coverage included changed validators and acceptance rules, expired freshness, runtime-environment drift, necessary multi-boundary validation, retry ownership and idempotency, temporary schema compatibility, low-impact Tier 5 work, already-approved Tier 5 execution envelopes, production web-app migration, long-task evidence invalidation, exhausted cloud-validator budgets, and unsuitable reuse candidates.
- One Ultra deep-matrix response retained the correct v1/v2 compatibility control and removal gates but did not explicitly name current v1 and mixed-version fixtures in its focused-test list. This isolated precision omission did not justify adding another universal instruction.
- One Ultra response described future agreement for read-only scheduler comparison conservatively; the scenario requested a design recommendation rather than execution, so this did not create an actual interruption and did not justify another universal rule.
- Candidate-only acceptance was used because this release does not claim a measured improvement over v0.6.1, and the user explicitly requested Max and Ultra coverage. Existing v0.6.1 routing evidence remains unchanged.
- Generated evaluation run logs were not retained in the repository.
