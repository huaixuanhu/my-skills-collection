# design-authorship v0.1.0

Date: 2026-08-28

Status: validated local candidate

## Scope

- Direct, redesign, critique, and verify UI, interaction, slides, presentation-like HTML, and explanatory diagrams from real content, audience, task, state, and project context.
- Separate design authorship from format construction: this skill sets and verifies direction while the relevant UI, PPTX, image, or diagram skill and tool builds the artifact.
- Route linear presentation HTML through slide logic and state-changing HTML through UI and interaction logic.
- Compose with `human-ai-governance` or `scaffold-research-task` only when their separate project-wide or research-task concerns are genuinely present.

## Human Alignment and Concept Images

- New UI, material redesign, and new interaction patterns require human confirmation or explicit delegation for relevant desktop, mobile, intermediate responsive, input, interaction, system, overflow, continuity, and motion states before implementation.
- Established systems first expose behavior inferred from code, tokens, components, and screens; bounded repairs ask only about affected gaps.
- Greenfield UI and material visual replacement actively offer a concept-image pass when visual information would otherwise travel mainly through prose.
- Slides and presentation-like HTML offer the pass only when original imagery, atmosphere, material, metaphor, or composition materially improves the story.
- The current official OpenAI name is **GPT Image 2**, with API model ID `gpt-image-2`. Generic image-generation tools remain unattributed unless their underlying model is verified.
- Concept images calibrate visual direction. They do not establish exact content, product behavior, component semantics, responsive states, accessibility, feasibility, brand approval, or factual evidence.

## Design Boundary

- Familiar fonts, cards, grids, gradients, colors, radii, or animations remain available when the artifact context supports them.
- The package contains no aesthetic lint script, fixed style recipe, numerical taste gate, global visual-memory store, or universal completion condition derived from subjective critique labels.
- Critique uses rendered artifacts and task-specific acceptance criteria. Severity labels prioritize findings without pretending to quantify taste.
- Private screenshots, confidential data, unreleased assets, and third-party material require authorization before use with a separate image service.

## Skill Catalog

- `SKILLS_INDEX.yaml` is the machine-readable routing and management source; `SKILLS_INDEX.md` is its validated human-readable view.
- The catalog records exact skill coverage, routing class, lifecycle, implicit or explicit invocation policy, positive and negative routing cues, and common composition.
- `human-ai-governance` is cross-cutting; `design-authorship` and `scaffold-research-task` are task-specific and semantically invoked when installed and matched.
- Live installation state is reported by `scripts/manage_skills.py list` and deliberately stays outside Git because it can change independently.
- The catalog cannot install a skill, force platform invocation, grant task authority, or replace the skill's own metadata.

## Release Boundary

This candidate changes canonical repository files only. It does not commit, push, tag, publish, install `design-authorship`, install `scaffold-research-task`, alter the existing `human-ai-governance` installation link, send assets to an image model, or change a downstream project.
