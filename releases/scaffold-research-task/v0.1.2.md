# scaffold-research-task v0.1.2

Date: 2026-09-07

Status: validated candidate; scoped Git publication authorized

## Change

Model experiments can now use the skill to maintain a full dimension map and a compact current-experiment card throughout planning, execution, interpretation, restarts, and handoffs. This route works directly in an existing experiment's protocol or design notes without invoking the scaffold generator.

The map distinguishes setting groups from independent factors, nested configuration-to-arm mappings, bundled training settings, population grouping, replication, and evaluation views. Its opening summary names and counts the tracked groups and currently changed settings without substituting a run count for a dimension count. The current card states the actual comparison, fixed conditions, separate and aggregated dimensions with support and weights, and score definition. On a switch it records changed dimensions, retained controls, and the impact on earlier comparisons. Completed results retain their original slice identity.

The guidance distinguishes conditional comparisons, marginal scores and contrasts, and separate group results. It keeps training loss, evaluation metric, prediction length, scored day/window, averaging order, and checkpoint selection identifiable. It also separates logical training identities from retries, scheduler jobs, prediction artifacts, and score rows. Missing or changed comparison support must remain visible.

## Scope and Compatibility

The detailed reference is `skills/scaffold-research-task/references/experiment-orientation.md`. Existing architecture and configuration templates carry the map and current-slice guidance. Routing, lifecycle, governance, and adaptation references point to the same owner rather than creating a parallel research plan.

No generated paths or manifest keys change. Schema 1 remains in use. The validator accepts v0.1.0, v0.1.1, and v0.1.2 generator identities, and checks original document markers without rewriting existing projects. Earlier layouts need not add orientation sections to remain structurally valid. This is guidance for source-backed experimental reasoning, not a machine check of scientific validity.

The user's default display choice is the compact card, with the full map retained in documentation and expanded on design changes or request. A further user-requested refinement makes the card start design proposals and slice changes with one logical line: total design dimensions, current varied dimensions, current marginalized dimensions, marginalization rule, and fixed dimensions with actual values. This line uses short labels and English dimension names without parenthetical Chinese translations, while preserving the same map, nested or bundled relationships, and normal screen wrapping. This terminology preference applies to the compact line. The six setting groups and design line in the reference are illustrative; they do not claim the current configuration, results, or independent-factor count of the capstone project.

## Behavioral Evidence

An independent agent received the skill and a synthetic existing study consisting of notes, a protocol, and raw results. It received a realistic request to explain the design, current comparison, workload, and a prospective change from day7 to mean7 reporting. It did not receive an expected answer, repository tests, or the parent agent's conclusions.

The agent extended the existing notes with a full dimension map and compact position. It counted 12 logical training identities from nested configuration-arm choices, two states, and two seeds; distinguished three score views from new training; and retained seven completed results, one failed result, and four identities without receipts. It reported the observed state reversal, withheld the incomplete primary aggregate under the fixture protocol, and kept day7-based checkpoint selection intact when explaining mean7. It preserved the current day7 slice while describing the proposed reporting switch. The parent inspected the notes, source scope, and unchanged three-file layout.

A follow-up used the final guidance to explain dimension counts near the top of the same notes. The agent explicitly counted its existing 13 map rows as tracked setting groups, separated seven choice/replication groups from six controls/rules, and identified one actual changed setting: learning-rate policy. It treated the arm label as the identifier for that change and kept the 12-run workload count separate. This counts the fixture's chosen map representation, not 13 independent design factors. The existing stage number and single map were retained.

The generated fixture and agent outputs remain outside the repository. This bounded exercise supports the demonstrated orientation behavior; it is not a measured long-horizon reliability or cross-model performance result. The later one-line formatting refinement received source/template review and repository validation; it was not a new independent agent exercise.
