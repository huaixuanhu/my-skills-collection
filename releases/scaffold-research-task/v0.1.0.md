# scaffold-research-task v0.1.0

Date: 2026-08-17

Status: validated canonical release

## Scope

- Derive the smallest useful architecture for one research task from its deliverable, inputs, code, data, compute, evidence, and reproducibility needs.
- Support a lightweight literature profile, local model research, third-party remote research, and bounded integration inside an existing repository.
- Keep research-task evidence governance distinct from project-wide human-AI collaboration governance.
- Generate only inside an explicit target with a default dry-run, conflict-first inspection, no overwrite, and explicit repository-root opt-in.

## Design Boundary

- `base`, `model-research`, `third-party-source`, and `remote-compute` are composable structural modules.
- `governance-connect` records and preserves the host project's existing governance; it does not generate a second `AGENTS.md`, AI log, or preflight system.
- Third-party handling scales from citation, to local inspection or execution, to incorporation or redistribution. Model 5 SONNET's case-specific source stop is not a universal default.
- The generated manifest and files do not authorize source copying, data access, dependency installation, remote jobs, publication, commit, push, tag, or installation.

## Deterministic Evidence

- Package regression: passed.
- Scaffold behavior regression: passed, including lightweight profile selection, module composition, host-directory adaptation, default dry-run, repository-root protection, different-content, ancestor, and symlink conflict handling, idempotence, and unsafe path rejection.
- Scaffold validator regression: passed, including extra user files, missing paths, manifest drift, unresolved template tokens, marker checks, and governance-connect without generated governance files.
- Aggregate repository validation: passed for two skills and five regression scripts.
- Official Codex skill validator: passed.

## Forward-Test Evidence

- Completed five isolated task-level runs across four scenario families: literature review, local ML, third-party model plus Slurm, and a research package inside a mature governed repository.
- The literature scenario retained the six-file `base` scaffold and did not introduce code, environments, compute, or project governance.
- The local ML scenario selected `base` plus `model-research`, preserved one versioned local data contract, and omitted third-party and remote modules.
- The mature-repository scenario selected package-local `model-research` plus `governance-connect`, inherited the root gate, and kept root registration separately reviewable.
- The first third-party plus Slurm run correctly separated citation, inspection, incorporation, access, smoke, and research-result evidence, but unnecessarily preferred an outside-repository checkout for Level 2 inspection. The skill was revised to accept any host-approved ignored or external location, and a fresh isolated retest applied that proportional rule correctly.
- Generated evaluation run logs were not retained in this repository.

## Release Boundary

This release changes the canonical skill package, deterministic tests, root skill index, changelog, and release evidence only. It does not alter `human-ai-governance`, downstream research repositories, installed skill links, remote systems, data, source checkouts, or publication state.
